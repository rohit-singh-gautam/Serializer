# Accessibility

Serializer aims to make its documentation, contribution process, and development
tools usable by people with different access needs. Accessibility improvements
and reports of barriers are welcome.

## Project surfaces and limitations

Schemas, generated source, command-line diagnostics, and most documentation are
text-based. Documentation can be read on GitHub or locally in a Markdown reader;
schemas can be edited in a text editor and compiled from the command line. See the
[README](README.md) for entry points and the
[build guide](docs/build_and_generation.md#build-and-test) for platform prerequisites
and verification limits.

These text-based workflows can help with alternative ways of accessing the
project, but they do not establish accessibility conformance. The project has not
documented a comprehensive accessibility audit or an assistive-technology test
matrix. Usability also depends on the browser, terminal, editor, and assistive
technology being used. Diagrams and wide code examples or tables may need
additional text explanations or layout improvements.

## Report a barrier

Use the [bug report form](https://github.com/rohit-singh-gautam/Serializer/issues/new?template=bug_report.md)
and describe the task, affected page or tool, expected behavior, and the barrier.
If useful, include your operating system, browser or editor, and assistive
technology versions. Screenshots are optional; a text description is enough.
You do not need to disclose a disability or medical information.

For a private report, email [rohit@singh.org.in](mailto:rohit@singh.org.in).
Reports will help prioritize improvements; there is no guaranteed resolution
time. When contributing documentation, use descriptive links, clear headings,
and text explanations for visual information, and avoid relying on color alone.
