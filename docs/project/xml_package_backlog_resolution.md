# XML and package backlog resolution

Compiler/runtime **2.34.0**, schema language **1.24.0**, editors **2.0.19**.
This resolves the thirteen retained XML/package requirements in the
[tracker](../pending.md#xml-and-package-backlog). Closure includes implemented
work, reconciliation with completed OPC requirements, and explicit decisions
against unbounded or unspecified extensions. It does not turn every proposed
combination into a supported feature. Only new implemented capabilities enter the
[implementation catalog](completed_requirements.md); reconciled parent IDs remain
in the tracker and this ledger.

The selected package contract is **OPC fifth edition**, using the documented
ASCII part-name, contiguous archive and complete-rewrite profile. The selected
**3MF Core 1.4 combined owning graph is C++/Python only**. Generic supported
XML/XSD mappings and owning package facades cover all eleven outputs. Other
backends continue to reject that combined Core graph explicitly. XSD validity
alone establishes neither mesh/application semantics nor package conformance.

## Evidence and remaining work elsewhere

The dates and compiler/source hashes in each verification record are authoritative.
Existing OPC results are reused as evidence for the same contract, not relabeled
as new runs or as qualification of every combination. The 2.34 records identify
the new authoring, package, Python routing, HTML and editor checks separately.

The external IDs above retain their current states in their own tracker sections.
Their work is deferred from this XML/package closure, not completed or reprioritized
here. Future requests for excluded features need a concrete new contract and
qualification gate rather than reopening an unlimited parent by implication.
