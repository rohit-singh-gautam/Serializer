## Other native protocols, allocation and provider controls

Fresh executions of `codec_benchmark 200` and `codec_allocation_profile 200`
each produce **80 rows**: scalar, short-text, long-text and nested-collection
workloads across JSON, positional, integer-key and string-key protocols, with
fresh-fit, growth, reuse and decode profiles. Nine samples per case retain their
minimum/median/maximum. The [timing CSV](data/native_cpp_timing_2026_10_24.csv)
and [allocation CSV](data/native_cpp_allocations_2026_10_24.csv) preserve the
separate uninstrumented/instrumented results. For example, reused scalar JSON
encoding records zero requested allocations, while fresh-fit encoding requests
one 96-byte output allocation. Instrumented timing includes the observer cost.

The generated-Python compression benchmark also completes all six formats:
NONE, GZIP, ZLIB, DEFLATE, Zstandard and LZ4. It uses fixed reproducible workloads,
five untraced timing calls, a separate traced-allocation call and independent
provider-native baselines after actual native serialization. Providers are Python
zlib **1.3.1.zlib-ng**, stdlib Zstandard **1.5.7**, Python LZ4 **4.4.5** with
liblz4 **1.9.4**. These differ from the C++ optional-provider deployment.

a reproducible current baseline and ordinary-byte preservation, without an
isolated earlier-release speed-regression threshold.
