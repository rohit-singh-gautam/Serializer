# Portable XML Unicode patterns - 22 October 2026

Compiler/runtime **2.28.0**, schema language **1.21.0**. The bounded portable
XML Schema pattern compiler now lowers Unicode category and block escapes,
character-class escapes and recursive class subtraction into the same immutable
Thompson range instructions already consumed by all eleven generated outputs.
Generated execution uses no host regex or runtime Unicode provider.

Implemented character sets include `\p{...}`/`\P{...}` major and minor general
categories, `Is...` blocks, `\s\S\d\D\w\W\i\I\c\C`, negated classes and
rightmost recursive subtraction. Name escapes use XML 1.0 fifth-edition name
ranges; whitespace and word escapes follow the XML Schema character-set
definitions. Empty results such as `[a-[a]]` remain valid empty sets. Existing
literal `^`/`$`, alternation, grouping, repetition and complete pattern-facet
semantics remain unchanged. Special groups, lookaround, backreferences and
unknown properties are rejected rather than delegated to a different dialect.

Unicode general categories and blocks are pinned to Unicode **17.0.0**, with
historical Unicode 3.0/3.2 block aliases for existing XSD spellings. The tracked
table records its official source hashes and is regenerated by
`qualification/generate_xml_unicode_tables.py`. `LICENSE-UNICODE` accompanies
the table. Regenerating from those retained official inputs reproduces the
tracked table byte for byte. Interval union, complement and subtraction normalize disjoint sorted
ranges before instruction emission. Schema work, allocation, recursion and
instruction caps still admit the immutable program before publication; runtime
input/work policies still apply during matching.

The shared corpus contains twelve independent character-set families: major and
minor categories, CJK and Greek letters, nested and negated subtraction, Arabic
decimal digits, exact XML whitespace, XML word classes, name starts/continuations
and the complement escapes. Existing inherited pattern facets, nullable cycles,
literal anchors, defaults and resource boundaries remain in the qualification.

Original XML and emitted XML are checked by a separate JAXP XSD 1.0 process
against the original schema. No generated model normalization changes the
documents given to that oracle. The focused native test run also passes all
nine pattern compiler tests and the scalar-contract suite. Invalid regex/schema
generation preserves previous destination artifacts.

Retained execution logs are `out/opc-pattern-{cpp-final,native,java,csharp,go,python,javascript,kotlin-final,swift-final}.log`.
Kotlin and Swift final logs contain successful execution of the expanded
88-case corpus; earlier interrupted mobile builds are not completion evidence.

## Independent provider boundary

The installed libxml2 engine disagrees on two valid boundaries: CJK letters in
`\p{L}` and the retained `e` branch of nested subtraction
`[a-z-[d-f-[e]]]`. JAXP accepts the untouched positive documents and rejects
their negative controls. Compiler tests retain those exact portable decisions
and compare libxml2 on its working subset. The all-output qualification uses
JAXP for the Unicode pattern corpus; other existing scalar/union suites retain
their original independent providers.

The lowering follows the [XML Schema 1.0 regular-expression specification](https://www.w3.org/TR/xmlschema-2/#regexs).
The frozen data comes from official [UnicodeData.txt](https://www.unicode.org/Public/17.0.0/ucd/UnicodeData.txt)
and [Blocks.txt](https://www.unicode.org/Public/17.0.0/ucd/Blocks.txt), with aliases
from the official historical block files.
