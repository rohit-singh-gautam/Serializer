# Backend field-default declaration locations - 24 October 2026

Compiler/runtime **2.32.2** repairs missing declaration locations in portable
field-default errors. Schema language **1.23.0**, generated public APIs, wire
identities and editor packages **2.0.17** remain unchanged.

Previously, a language 1.13 `uint8` default of `999` failed in a non-C++ backend
with only its member name. The same missing context affected older includes,
concrete generic copies, enum qualifiers, floating overflow, malformed string
escapes and unsupported legacy collection defaults. A newer including file did
not supply the actual declaring member's coordinates.

Backend rejection now prefixes the existing reason with the retained
`file:line:column: member name:` location. The exception remains
`std::invalid_argument`; no successful recognition or generated bytes change.
The native literal normalizer used by typed parser binding remains untouched,
avoiding duplicate parser prefixes. Public AST callers without complete source
coordinates retain the previous message. The helper allocates only on failure.
Serialization paths are untouched; successful literal processing performs no
diagnostic formatting or allocation.

The regression matrix selects C++ and each of the ten non-C++ outputs in one
invocation, including paired TypeScript/JavaScript output. Eight cases per output
cover direct and transitive declarations and copied generic fields. Rejection
must preserve prior artifact contents and timestamps, including the depfile.
Separate native C++ generation controls preserve existing opaque/legacy
acceptance; these intentionally invalid host literals are not SDK success claims.

This completes **SC02e** within the field-default diagnostic scope above.
