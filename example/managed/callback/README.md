# 2. Let the transaction call a named function

Read [point.serializer](point.serializer), then [main.cpp](main.cpp).
The point class is generated by Serializer.

`move_point(point& value)` is the callback. The program passes that function
to the real `transaction.update(move_point)` operation. The runtime calls it
synchronously with a reference to the transaction's isolated candidate point.

The recipient code is `transaction::update` in
[managed.hpp](../../../include/rohit/managed.hpp):

```cpp
std::invoke(std::forward<Callable>(callback), *candidate_);
```

Here, `callback` is `move_point` and `*candidate_` is the generated point.
The assignments in `move_point` change that candidate. Successful completion
of `execute_transaction` publishes the changes. Check the returned outcome
before using the result.

Expected output:

```text
point: (10, 20)
```

This uses the runtime's existing low-level update API to make the callback
recipient visible. The callback must not retain a mutable reference or modify
`persistent_id`. Normal application code should use the generated editors,
as in the next example.

Build target: `managed_point_callback`. See [build instructions](../README.md#build-the-point-examples).
